# PRD: OpenScreen Personal Creator Edition

- Статус: **READY WITH CONDITIONS**
- Владелец: Александр
- Дата: 1 августа 2026
Текущий вертикальный срез: сохранение основной записи в Яндекс Диск

## 1. Executive decision summary

OpenScreen используется как персональная основа для быстрого производства продуктовых видео.
Мы сохраняем исходный recorder-first flow и добавляем функции только там, где они сокращают путь
`идея → запись → готовый файл → публикация`.

Первый срез загружает основной файл записи в публичную папку `OpenScreen Exports` на Яндекс Диске.
Загрузка выполняется в фоне. Опциональная локальная очистка включена по умолчанию, но срабатывает
только после серверной проверки файла и выхода из редактора.

## 2. Evidence and assumptions

Факты:

- пользователь прямо запросил автоматическое сохранение записи в Яндекс Диск;
- OpenScreen уже создаёт единый `RecordingSession` на Windows, macOS и browser pipeline;
- локальный файл доступен сразу после завершения записи;
- Яндекс Диск предоставляет REST API для desktop-приложений.

Предположения:

- основной Job — резервное копирование сырой записи, а не публикация финального экспорта;
- достаточно загружать `screenVideoPath`, без отдельного webcam-sidecar;
- ручное получение OAuth-токена допустимо для личного пилота;
- публичная папка находится по пути `disk:/OpenScreen Exports` в корне личного Диска.

Самое рискованное предположение: автозагрузка сырой записи создаёт больше ценности, чем загрузка
только готового экспорта. Проверка — использовать функцию на 10 реальных записях и сравнить, какие
файлы фактически открываются с другого устройства.

## 3. Goal and metrics

Focus outcome: после остановки записи пользователь не выполняет ручных действий для создания
облачной копии.

Метрики пилота:

- не менее 95% включённых загрузок завершаются успешно;
- локальный редактор открывается без ожидания сети;
- 0 потерянных локальных записей при ошибке API;
- 0 локальных удалений без совпадения типа и размера удалённого файла;
- медианное время настройки интеграции — до 5 минут;
- после 10 записей принято решение: raw upload, export upload или оба сценария.

## 4. Segment, role and Job

Beachhead-сегмент: один создатель продуктовых видео, который записывает демо, walkthrough и
контент для YouTube, соцсетей, документации и продаж.

UX Job:

> Когда я останавливаю важную запись, я хочу автоматически получить независимую облачную копию,
> не задерживая переход в редактор, чтобы не потерять материал и продолжить работу с другого
> устройства.

## 5. Value proposition

Меньше ручных операций и ниже риск потери исходника. Интеграция остаётся частью личного workflow,
не превращая OpenScreen в универсальный cloud storage клиент.

## 6. MVP scope

Входит:

- настройка OAuth-токена и относительной папки;
- системное шифрование токена через Electron `safeStorage`;
- переключатель «загружать после каждой записи»;
- переключатель «удалять локальную запись после загрузки», включённый по умолчанию;
- проверка публичной ссылки папки и размера загруженного файла;
- фоновая последовательная очередь;
- потоковая загрузка файла без буферизации целиком в RAM;
- один повтор при HTTP 429/5xx;
- toast и системное уведомление об успехе или ошибке;
- одинаковый вызов после browser, Windows-native и macOS-native записи.

Non-goals:

- полный OAuth Authorization Code + PKCE flow;
- загрузка webcam-sidecar, cursor telemetry и `.session.json`;
- загрузка финального MP4/GIF после экспорта;
- создание публичной ссылки;
- очередь, переживающая перезапуск приложения;
- несколько аккаунтов или облачных провайдеров;
- аналитика, отправляемая во внешние системы.

## 7. User journey and states

1. Пользователь открывает панель Яндекс Диска в HUD.
2. Вставляет OAuth-токен с доступами `cloud_api:disk.read` и `cloud_api:disk.write`.
3. Проверяет путь `OpenScreen Exports`, автозагрузку и локальную очистку.
4. Приложение сверяет папку с заданной публичной ссылкой и сохраняет токен зашифрованно.
5. После остановки записи локальная сессия завершается как обычно.
6. Редактор открывается сразу, а upload выполняется в фоне.
7. Пользователь получает подтверждение upload; локальная запись удаляется после выхода из editor.

Состояния: загрузка настроек, не подключено, подключено/выключено, подключено/включено,
сохранение, upload, success, auth error, quota/network error, disconnect.

## 8. Functional requirements

- FR-1: выключенная интеграция не делает сетевых запросов.
- FR-2: renderer никогда не получает сохранённый токен обратно.
- FR-3: IPC принимает для upload только файл внутри каталога записей OpenScreen.
- FR-4: удалённый путь нормализуется внутри `disk:/OpenScreen Exports` и сверяется с публичной ссылкой.
- FR-5: локальный файл удаляется только при включённом параметре, совпадении удалённого размера и
  отсутствии активного редактора.
- FR-6: открытие редактора не зависит от результата upload.
- FR-7: повторная отправка одной записи идемпотентна (`overwrite=true`).

## 9. Non-functional requirements

- без новых runtime-зависимостей;
- TypeScript strict-safe;
- токен не логируется и не хранится в `localStorage`;
- память не растёт пропорционально размеру видео;
- интеграция не меняет native recorder contracts;
- все ошибки преобразуются в понятное пользовательское сообщение.

## 10. Release, fallback and support

Пилот запускается на ветке `custom`, а `main` остаётся зеркалом upstream. При проблемах пользователь
выключает автозагрузку или отключает аккаунт; стандартная запись и редактор продолжают работать.

Условия завершения пилота:

- typecheck и unit-тесты проходят;
- выполнена реальная запись и upload на Windows;
- проверены invalid token, offline и quota error;
- принято решение о следующем срезе: export upload или persistent retry queue.

## 11. Acceptance criteria

- токен успешно проверяется и сохраняется;
- после записи файл появляется в выбранной папке Яндекс Диска;
- success-уведомление появляется только после проверки удалённого файла;
- при включённой очистке файл остаётся доступен редактору и удаляется после выхода из него;
- приложение открывает редактор до завершения upload;
- при отключённом интернете локальная запись доступна и пользователь видит ошибку;
- после disconnect зашифрованный токен удалён из настроек;
- `main` можно fast-forward синхронизировать с `upstream/main`.
