# Product and architecture decisions

Этот журнал фиксирует решения персональной кастомизации, чтобы они не исчезали внутри кода и
следующих prompt-сессий.

## D-001 — `main` остаётся зеркалом upstream

Решение: не коммитить персональные функции в `main`. Релизная персональная версия живёт в
долгоживущей ветке `custom`; новые изменения начинаются в коротких feature-ветках от `custom`.

Причина: `main` можно обновлять через `git merge --ff-only upstream/main`, а различия и конфликты
видны отдельно.

## D-002 — Интеграции изолируются от recorder pipeline

Решение: облачные провайдеры реализуются в `electron/integrations/` и вызываются после создания
`RecordingSession`. Нативные Windows/macOS helper contracts не меняются.

Причина: native capture — самая хрупкая и активно меняющаяся часть upstream. Изоляция снижает
стоимость каждого обновления.

## D-003 — Локальная запись является source of truth до подтверждения облака

Решение: Stop всегда создаёт локальный draft и не делает сетевых запросов. При включённой очистке
export и source bundle удаляются только после проверки типа и размера удалённого файла и только
после выхода из текущего редактора. Ошибка export, upload или проверки сохраняет локальную запись.

## D-004 — Проверяемая пользовательская папка Яндекс Диска

Решение: использовать `cloud_api:disk.read` и `cloud_api:disk.write` для пути
`disk:/OpenScreen Exports`. Перед сохранением настроек и каждым upload приложение проверяет, что
папка соответствует публичной ссылке `https://disk.yandex.ru/d/GKhvA2QkXOBe2g`.

Причина: публичная папка находится вне изолированного `app:/`, а чтение метаданных необходимо для
проверки назначения и размера загруженного файла.

## D-005 — Токен хранится только в main process

Решение: renderer передаёт токен один раз через IPC; main process шифрует его Electron
`safeStorage`. Обратно возвращается только `connected: boolean`.

Запрещено: `localStorage`, `.env` в репозитории, открытые JSON-конфиги, логирование token/body.

## D-006 — Manual token перед полным OAuth

Решение: для личного pilot используется OAuth debug token. Authorization Code + PKCE добавляется
только если интеграция становится продуктовой или используется несколькими людьми.

Причина: это самый дешёвый RAT ценности; client registration и redirect UX пока не являются
критическим путём.

## D-007 — Публикуется итоговый MP4, а не raw screen track

Решение: Publish сначала запускает штатный editor export, затем main process загружает полученный
MP4. Это правило одинаково для фоновой публикации сразу после Stop и для Publish из редактора.

Причина: raw screen track не содержит webcam composition, cursor overlay и правки. Пользователь
ожидает получить на Диске готовый к просмотру ролик.

## D-008 — Персональный HUD фиксирован на русском и horizontal layout

Решение: убрать language picker, system-language prompt, Notes и vertical tray. Русский становится
default locale, webcam получает живой preview, а cursor mode описывает текущее состояние и
последствия для редактора.

Причина: это персональная сборка для одного workflow; невостребованные controls создают шум и
ухудшают понимание основного сценария.

## Как добавлять решения

Для каждого нового решения указывать дату, контекст, выбранный вариант, альтернативы, причину,
последствия и условие пересмотра.
